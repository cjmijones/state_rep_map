# Official legislative votes and agendas: source plan

Checked 2026-09-27. This note extends [voting-history.md](voting-history.md), concentrating on sources published by the chambers themselves. “Votes” below means **recorded roll calls** with member positions; voice votes and unanimous-consent actions have no individual vote record. An agenda is a proposed schedule and can change or be cancelled. The [Senate's vote guide](https://www.senate.gov/legislative/HowTo/how_to_votes.htm) makes the first distinction explicit.

## Federal sources

| Data | Best official machine source | Access and limits |
| --- | --- | --- |
| U.S. House floor roll calls | [Clerk's session index](https://clerk.house.gov/evs/2026/index.asp) links every 2026 roll call; each [vote page](https://clerk.house.gov/Votes/20261) has an XML view. Direct XML pattern: `https://clerk.house.gov/evs/2026/roll001.xml`. The [House XML site](https://xml.house.gov/) documents the roll-call schema and says XML votes run from 1990 to present. | Public, no key. Crawl the index, then fetch by `(Congress, session, roll number)`. This is preferable to deriving a vote list from bills because procedural and other non-bill votes also appear. |
| U.S. Senate floor roll calls | [Senate XML index](https://www.senate.gov/general/common/generic/XML_Availability.htm) links roll-call list and detail XML. Current-session pattern: `https://www.senate.gov/legislative/LIS/roll_call_lists/vote_menu_119_2.xml`; detail pattern: `https://www.senate.gov/legislative/LIS/roll_call_votes/vote1192/vote_119_2_00244.xml`. [Vote tables](https://www.senate.gov/legislative/LIS/roll_call_lists/vote_menu_119_2.htm) provide a human-checkable index. | Public, no key advertised. Senate says vote tallies normally appear within an hour and its tables reach back to the 101st Congress. Test access from the actual refresh host: Senate XML has been reported as returning 403 to some automated clients in a [Congress.gov API issue](https://github.com/LibraryOfCongress/api.congress.gov/issues/441). Keep a last-good snapshot and surface refresh failures. |
| House bills and committee meetings | [Congress.gov API v3](https://api.congress.gov/) supports `/v3/bill/{congress}/{billType}/{billNumber}/actions` and `/v3/committee-meeting/{congress}/house` with meeting details at `/v3/committee-meeting/{congress}/house/{eventId}`. The [House Committee Repository](https://docs.house.gov/committee/Help.aspx) publishes an XML file for each posted meeting, with scheduled/rescheduled/postponed/cancelled status. | Congress.gov needs a free API key. Its [official repository](https://github.com/LibraryOfCongress/api.congress.gov) states 5,000 requests/hour, 250 maximum items/page. Committee meeting data is an agenda/notice, not a member vote ledger. |
| House floor agenda | [House Document Repository's “Bills This Week”](https://docs.house.gov/floor/) has an XML file per legislative week, according to its [Help page](https://docs.house.gov/committee/Help.aspx); it contains measures that **may** be considered. A live XML example is `https://docs.house.gov/floor/Download.aspx?file=%2Fbillsthisweek%2F20260914%2F20260914.xml`. The House Majority Leader and Rules Committee supply it. | Public XML, no key stated. Read the current week's XML link from the page instead of guessing a dated filename. Do not label these items guaranteed votes. |
| Senate floor and committee agendas | [Senate XML index](https://www.senate.gov/general/common/generic/XML_Availability.htm) links the [floor schedule XML](https://www.senate.gov/legislative/schedule/floor_schedule.xml) and [hearings/meetings XML](https://www.senate.gov/general/committee_schedules/hearings.xml), along with a tentative floor schedule. The [Senate floor activity archive](https://www.senate.gov/legislative/LIS/floor_activity/all-floor-activity-files.htm) links daily activity XML, Calendar of Business, and Executive Calendar. | Public, no key stated. The floor schedule is short-horizon and tentative. Committee notices can change, so preserve the status/update time and link to the source. |
| Optional House vote API | Congress.gov offers `/v3/house-vote/119/2`, detail `/v3/house-vote/119/2/{voteNumber}`, and member rows at `/members`. | **Beta and incomplete for a canonical House ledger**: the [official coverage note](https://github.com/LibraryOfCongress/api.congress.gov/blob/main/Documentation/HouseRollCallVoteEndpoint.md) says it currently includes 118th/119th House roll calls associated with legislation and excludes non-legislation votes such as Speaker elections. There is no Senate vote endpoint in the [published API resource list](https://api.congress.gov/). |

The [House Repository help](https://docs.house.gov/committee/Help.aspx) says its XML files are not digitally signed and the House cannot guarantee authenticity once others republish them. Retain the official URL, retrieval timestamp, raw content hash, and a link back to the chamber page. The [Senate guide](https://www.senate.gov/legislative/HowTo/how_to_votes.htm) calls the Congressional Record the official record of recorded floor votes; use it as an audit/reference source if a parsed vote conflicts with a chamber feed.

Live requests on 2026-09-27 returned parseable XML from the Senate floor and committee feeds and the House's September 14 weekly floor file. This confirms retrieval from this machine; it does not guarantee future availability or that a tentative item becomes a vote.

## State legislatures: official data is state-specific

There is **no uniform official 50-state vote-and-agenda API identified here**. Build one adapter per state/chamber/source format, after confirming the state legislature owns or sponsors the site. These first-party examples show the range of workable routes:

| State | Official programmatic path | Scope and caveat |
| --- | --- | --- |
| California | [Legislative Information bulk downloads](https://downloads.leginfo.legislature.ca.gov/) and its [PUBINFO readme](https://downloads.leginfo.legislature.ca.gov/pubinfo_Readme.pdf). `pubinfo_2025.zip` is a session dump; `pubinfo_Mon.zip` etc. contain daily additions. Tables include `BILL_DETAIL_VOTE_TBL`, `BILL_SUMMARY_VOTE_TBL`, `COMMITTEE_AGENDA_TBL`, and `COMMITTEE_HEARING_TBL`. | No key stated. The current full dump is about **1.2 GB** and daily full extracts about **1.1 GB** in the [directory listing](https://downloads.leginfo.legislature.ca.gov/); use delta files after one controlled backfill. Table descriptions are in the readme, which should guide parsing. |
| New York | The [New York Senate's Open Legislation](https://legislation.nysenate.gov/) is its own public JSON API backed by Legislative Bill Drafting Commission data. Bill detail `/api/3/bills/{sessionYear}/{printNo}` includes floor/committee `votes` and member vote codes; [bill updates](https://openleg.nysenate.gov/static/docs/html/bills.html) can be filtered with `filter=VOTE`. [Committee agendas](https://openleg.nysenate.gov/static/docs/html/agendas.html) use `/api/3/agendas/{year}/{agendaNo}` and `/api/3/agendas/meetings/{from}/{to}`; [floor calendars](https://openleg.nysenate.gov/static/docs/html/calendars.html) use `/api/3/calendars/{year}/{calendarNumber}`. | Free API key by sign-up. The official calendar documentation says Assembly calendar data is not supplied; do not treat this as complete agenda coverage for both NY chambers. Validate the vote coverage of each chamber independently. |
| Washington | The legislature's [Legislative Web Services](https://wslwebservices.leg.wa.gov/) are free SOAP/XML services. [GetLegislationByYear](https://wslwebservices.leg.wa.gov/legislationservice.asmx?op=GetLegislationByYear) enumerates bills; [GetRollCalls](https://wslwebservices.leg.wa.gov/legislationservice.asmx?op=GetRollCalls) returns bill roll calls with `VoteDate`, `Motion`, and individual `Vote` rows containing `MemberId` and vote code. Live probe: `https://wslwebservices.leg.wa.gov/legislationservice.asmx/GetRollCalls?biennium=2025-26&billNumber=1217` returned 11 roll calls, with 98 member rows on the first. [GetCommitteeMeetings](https://wslwebservices.leg.wa.gov/committeemeetingservice.asmx?op=GetCommitteeMeetings) lists meetings by date range; [GetCommitteeMeetingItems](https://wslwebservices.leg.wa.gov/committeemeetingservice.asmx?op=GetCommitteeMeetingItems) lists agenda items by `agendaId`. A two-day January 2026 meeting query returned 32 meetings. | Strong first-party **votes plus agendas** pilot, though rolls are bill-centered. A test request for bill 1001 returned no rolls, which is a normal empty bill result and does not indicate feed failure. The legislature warns that response time and availability are not guaranteed. |
| Maine | The legislature publishes [House roll calls](https://legislature.maine.gov/house/Documents/RollCalls), [Senate roll calls and calendars](https://legislature.maine.gov/senate/senators-resource-page/9350), and the [House Advance Journal and Calendar](https://web.legislature.maine.gov/house/HouseActivities/FAQs). | Official HTML/PDF route where no supported API was identified. Crawl archive pages carefully and preserve the original PDF/page link. Maine's House explains that the calendar is the official daily agenda and that roll calls are recorded separately from other decisions. |

For the remaining states, perform a source inventory before writing parsers: official legislature root, House and Senate roll-call index, daily journal, floor calendar, committee notice/agenda, downloadable feed/API, session identifier, member identifier, update semantics, and any access policy. Record a verified source URL and sample document for each chamber. [USAGov's state-government directory](https://www.usa.gov/state-governments) can help locate state sites, but each vote/agenda connector must be checked against the legislature's own page. A blank API result is **unknown coverage**, not proof a member did not vote.

## Current project gap

The app's [federal refresh script](../../state-rep-backend/state_rep_map_builder/refresh_federal_data.py) already reads official House and Senate roll-call XML, but writes only the newest ten votes by default, allows at most 30, and is fixed to the 119th Congress, second session, in 2026. The [Congress view](../../state-rep-map-visualizationo/app/congress/page.tsx) displays those snapshot votes; it has no floor or committee agenda import. The [state snapshot](../../state-rep-map-visualizationo/public/data/WA.json) has current members with Open States `ocd-person` IDs, while Washington roll calls use official numeric `MemberId` values. Joining them requires a checked person/term crosswalk, including effective dates, before a member's historical vote can appear on a district card. The state view currently has no roll-call or agenda panel.

## Recommended ingestion design

1. **Implement federal first.** Poll the House Clerk index and Senate XML vote-list at a modest cadence during session days; fetch new or changed vote details and recheck recent votes for corrections. In parallel, poll House weekly XML, Senate floor/committee XML, and Congress.gov committee-meeting updates. Store separate `roll_call` and `agenda_item` types.
2. **Normalize without losing provenance.** Keep raw source files, HTTP status/ETag or Last-Modified when supplied, `retrieved_at`, content hash, canonical official URL, source jurisdiction/chamber/session, and the parser version. Use `jurisdiction + chamber + session + roll_number` as the floor-vote key. Store a separate row for each member's position, linked to the officeholder **at the vote date**, not whoever serves the district now. Preserve the original vote code; translate it for display only.
3. **Treat schedules as mutable.** Upsert agenda events by official meeting/event ID and track published/updated/cancelled status. Allow events without a bill and multiple bills per event. Label floor items “may be considered”; never infer a recorded vote from an agenda or bill action.
4. **Add state adapters incrementally.** Start with WA's bill enumeration → roll-call details and date-range meeting queries; follow with CA bulk, NY JSON, and a state with official HTML/PDF roll calls such as ME. Each adapter declares covered chamber/session/date range and `votes`, `floor_agenda`, and `committee_agenda` capabilities separately. Only show a member-vote panel when individual records are available. Expand toward 50 states by verifying official endpoints state by state.
5. **Publish a small snapshot to the map.** Run imports server-side or in a scheduled job, validate vote totals and distinct member identities, then publish compressed per-jurisdiction/session JSON for the browser. Expose last successful refresh and source links. Alert on missing expected feed updates, parser breakage, HTTP 403/429, and sudden drops in count; keep the last known-good snapshot visible with its date.

This design keeps official records as the source of truth while making the browser fast and avoiding live scraping on each map click. The main open work is the 50-state source inventory and chamber-by-chamber coverage audit; it cannot be assumed from the four examples above.
